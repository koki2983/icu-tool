# tools：公開前の確認と、追加した文の元

目的：作業した環境が消えても、同じ確認と追加ができるように、道具を残す。
読む人：このアプリを直す人（人でも AI でも）。
ゴール：`index.html` を直したら、下の確認を回してから公開する。

## 公開の手順
1. `index.html` を直す
2. `<script>` の中身を取り出して `node --check` で文法を確かめる
3. `確認/` のスクリプトを回す（下の表）。エラーとはみ出しが 0 であること
4. `python3 確認/stamp.py` で版の日時を付ける（`index.html` の `APP_BUILD`）
5. コミットして `main` に push。1〜2 分で本番に出る
6. 本番の URL を引数にして、もう一度 3 を回す

## 確認のスクリプト（Node ＋ Playwright。引数は URL。省くと手元のファイル）
| ファイル | 見るもの |
|---|---|
| t5.js | 直接リンク（#k= #c= #p=）12 本が開くか |
| fg.js | 追加した図（pf_ で始まるもの）の文字が、枠からはみ出していないか。図を 1 枚ずつ画像にする |
| d5.js | 指定した項目と薬剤各論が開くか、主な図のはみ出し、数（知識・用語） |
| pr.js | 全項目を開いて、薬の名前の併記と、画面のエラー |
| f1.js | 見出しの折りたたみ、見出しつきの直接リンク、すぐ報告の一覧、利用の記録 |
| s1.js | 照合の印、最近追加した項目、薬剤タブの見出しと絞りこみ |
| ck.js | チェック画面（#p=check）と、その中の ID |
| ex.js | 全項目の本文を JSON に書き出す（確認用の一覧のもと） |

## 元の文
`元の文/` は、`index.html` に入れた追加分の元（疾患、薬剤各論、図、折りたたみ、照合の印など）。
`index.html` が正で、ここは控え。直すときは `index.html` を直し、必要ならここも合わせる。

## してはいけないこと（理由つき）
- GitHub のトークンをリポジトリに入れない（公開リポジトリなので、誰でも読める）
- 患者さんを特定できる情報を入れない（アプリは公開されている）
- 固定 ID（`KID`）を変えない（チェックリストや直接リンクが切れる）
- 「当院の基準と医師の指示が優先」の一文を消さない（一般的な目安と、当院の決まりを取り違えさせないため）

## 確認の印と、更新の履歴（2026-11-13 に追加）

目的：医師・薬剤師が確認したあとに本文を直したとき、「確認済み」の印だけが残って読む人をだますことがないようにする。

1. `python3 tools/確認/stamp.py "今回の変更をひとことで"`：版の日時と、更新の履歴（`HIST`）を作り直す。ひとことは commit の題と同じにする。理由：履歴は git の記録から作るので、まだ commit していない今回の分は、ここで渡さないと 1 回おくれて出るから
2. `node tools/確認/verhash.js`：確認の印のある項目のうち、印のあとに本文が変わったものを一覧で出す（書きかえはしない）
3. `node tools/確認/verhash.js --write`：今の本文を「確認したときの本文」として控え直す（`VERH`）。確認の印を付けた・付け直したときだけ使う。ふだんの直しでは使わない。理由：使うと、「確認のあとに直した」ことが画面から消えるから
